# Rubric v1 — 睡眠健康 App Interface 評分標準

## 0. Metadata
- rubric_version: v1
- 建立日期: 2026-07-28
- 基於: Baseline 第一輪(版本 A/B/C/D) + 第二輪(版本 E/F/G)
- 產品定位: 幫都市人(香港職場為核心場景)日間卸載雜念、夜晚改善入睡困難嘅睡眠健康App
- 核心差異化: 解決失眠成因,而非單純追蹤睡眠結果或提供放鬆內容

---

## 1. 強制否決規則(Hard Constraints — Pass/Fail,不受權重影響)

任何一項不合格,該版本直接判 0 分,不進入加權計算,並於下一輪重做。

| 規則編號 | 規則內容 | 驗證方式 |
|---|---|---|
| HC-01 | Wind-Down 頁「minutes left」標籤與倒數數字不可重疊 | 截圖檢查 + 響應式測試(1分鐘/99分鐘顯示皆不可爆版) |
| HC-02 | 輔助色與背景色相不可為對立/互補色相(如深藍配橙紅) | 色相角度分析(需同色系或相鄰色系) |
| HC-03 | 輔助色飽和度不可超過 50%,不可出現螢光/鮮豔色 | HSL 飽和度數值檢查 |
| HC-04 | 核心動作(Brain Dump 入口、Checkpoint 按鈕)在任何頁面不可被遮擋或難以辨識 | 視覺熱區檢查 |
| HC-05 | 全局框架(頂部欄+底部導覽4分頁+FAB)與6個核心頁面不可增減或合併 | 架構比對 |

## 2. 評分維度與定義

總分 = (行為/可用性平均分 × 0.50) + (情緒/功能對齊平均分 × 0.35) + (純美觀/原創性平均分 × 0.15)

前提:必須先通過第1節全部強制否決規則,否則總分直接判0或列為「需重做」。

### 2.1 行為/可用性維度(權重 50%)

| 維度 | 定義 | 5分標準 | 1分標準 |
|---|---|---|---|
| 任務完成路徑長度 | 由入口到完成核心動作嘅撳擊步數 | Brain Dump 從 FAB 到完成記錄 2-3 步內完成 | 需 5 步以上或路徑不直覺 |
| 認知負荷 | 每個畫面要求用戶同時處理嘅決策/資訊量 | 每畫面只有一個主要決策 | 同時要求多項決策(如同時選作息類型又設通知) |
| 錯誤/誤觸風險 | 按鈕距離、大小、相鄰誤觸可能性(熄燈環境盲摸) | 核心按鈕觸控區≥44px,間距充足 | 按鈕過小或過近,易誤觸 |
| 中斷恢復力 | 操作中斷後能否保留草稿/進度 | 中斷後返回可完整接續 | 中斷後資料遺失,需重新輸入 |
| 情境切換流暢度 | 由日間場景到夜晚場景嘅心理轉換是否自然 | 記錄頁到 Wind-Down 入口直覺明確 | 需兜路徑(如經首頁)才找到入口 |
| 首次使用達成時間 | Onboarding 到首次成功使用核心功能嘅總時間 | 2分鐘內完成首次 Brain Dump | 超過5分鐘或流程繁瑣 |

### 2.2 情緒/功能對齊維度(權重 35%)

| 維度 | 定義 | 5分標準 | 1分標準 |
|---|---|---|---|
| 情緒安全感 | 畫面是否讓人覺得適合睡前使用 | 平靜、克制,無高刺激元素 | 資訊密集、色彩刺激,似普通生產力App |
| 資訊優先度 | MVP核心動作是否夠顯眼易撳 | Brain Dump輸入框、Checkpoint按鈕視覺權重最高 | 核心動作與裝飾元素視覺權重相同或更低 |
| 背景與輔助色和諧度 | 背景與輔助色色相關係、飽和度、明度搭配 | 同色系/相鄰色系,飽和度30-50%,明度階梯溫和(見2.2.1) | 對立色相或高飽和刺眼(觸發HC-02/03) |
| 圓角處理 | 按鈕/卡片邊角圓潤度 | 圓角半徑最少8-12px,無直角 | 方正直角,顯得銳利 |
| 操作直覺度(Active State) | 底部導覽被選中項目嘅視覺區分度 | 三層區分:bold icon+bold文字+dot indicator(參考版本D) | 僅單一視覺層區分(如僅顏色深淺) |

#### 2.2.1 色彩和諧度評分步驟(judge 推理指引)
1. 描述背景色的色相(hue)、飽和度(saturation)、明度(lightness)
2. 描述輔助色的色相、飽和度、明度
3. 判斷兩者色相關係:同色系/相鄰色系/對立色系
4. 判斷輔助色飽和度是否落在30-50%建議區間
5. 根據以上四點,對照5分制標準給分,並簡述理由

### 2.3 純美觀/原創性維度(權重 15%)

| 維度 | 定義 | 5分標準 | 1分標準 |
|---|---|---|---|
| 視覺一致性 | 6個頁面之間色彩、字體、間距是否統一 | 全頁面統一設計語言 | 各頁各自為政,風格不一 |
| 記錄呈現模式創意度 | 歷史記錄類頁面呈現手法 | 採用Memo/便條式呈現(參考版本C) | 純list呈現,缺乏互動感 |
| 原創性 | 是否有別於市面Calm/Headspace嘅記憶點 | 有明顯記憶點與差異化 | 與市面產品高度雷同 |

## 3. Persona Simulation(行為評分前置步驟)

評分行為/可用性維度之前,judge 必須先進入以下角色狀態,用第一人稱模擬走一次核心流程:

**角色設定**: 27歲香港上班族,OT到夜晚11點,現在凌晨1點,躺床40分鐘仍睡不著,腦中反覆想著工作訊息、deadline、人際磨擦。眼睛疲累、手指反應遲鈍,不想看太多字,只想快速卸下雜念然後放低手機。

**模擬任務**: 以此角色狀態實際走一次「打開App → 完成一次Brain Dump記錄 → 決定是否前往Wind-Down頁」流程。

**每一步須回答**:
1. 這一步需要撳幾多下?
2. 有沒有任何一刻需要停低超過2秒思考「這個掣是否做這件事」?具體位置與原因
3. 以疲累的視覺與反應能力,字體/按鈕大小是否看得清楚、撳得準確?
4. 完成這一步後,情緒上是否覺得「輕鬆了一點」,還是「還要想更多」?

**輸出格式**: 先用第一人稱敘事寫低模擬過程,再將四條問題答案整理做行為/可用性維度嘅實際評分依據。
